# WindowDock と WindowTabs の機能比較

## 調査範囲

- 調査日: 2026-11-27
- WindowTabs: `leafOfTree/WindowTabs` の v2026.11.20 README、CHANGELOG、リリースノートを参照。
- WindowDock: 現在の README と実装を参照。
- 公開資料上の機能比較であり、WindowTabs を実機ですべて検証したものではない。設定で任意に有効化する機能もある。

## まとめ

WindowDock は、ワークスペースの移動・リサイズ・最大化に中のウィンドウが追従する機能を実装し、WindowTabs と共通する基本価値に追いついている。タブ、複数ワークスペース、自動追加、分割表示も揃っている。

主な差は「ウィンドウをまとめて素早く切り替える」ための検索・直接選択と、グループを自動整理・編集する機能。WindowTabs は機能の幅が広いが、WindowDock は入れ子を含む最大 4×4 のペインや、表示中の複数ペインをひとつのタブとして扱うなど、独自のワークスペース表現を持つ。

## 主な機能の比較

| 分野 | WindowDock | WindowTabs | 差分 |
|---|---|---|---|
| ウィンドウのグループ化とタブ切替 | 対応。異なるアプリのウィンドウを同じワークスペースに登録 | 対応 | 共通する基本機能 |
| グループの移動・リサイズ | ウィンドウ操作にワークスペースと他ペインが追従 | グループ内ウィンドウが一緒に移動・リサイズ | どちらも対応。WindowDock は「ウィンドウを直接動かしたとき」の動作を設定可能 |
| 複数ワークスペース | 対応。切替、統合、保存・復元 | 対応。保存・復元、コマンドラインからの復元 | 共通。WindowTabs は復元時に未起動アプリを起動できる |
| 分割表示 | 入れ子を含む最大 4×4。境界調整、ペイン固定、複数ペインをひとつのタブにまとめる | グループ内の複数ウィンドウを分割表示。境界調整や分割操作あり | 両方対応。ペインのまとめ方とレイアウト表現が異なる |
| ウィンドウの追加 | ピッカー、「+」からアプリの新規ウィンドウを起動、タブバーへのドラッグ | 既存ウィンドウの追加、新しいウィンドウの追加 | 共通。WindowDock はアプリ選択から起動・追加できる |
| 新規ウィンドウの自動追加 | アプリ単位でワークスペースに追加 | アプリルールやグループ設定。タイトル、ウィンドウクラス、コマンドラインなどで分類 | WindowTabs のルールの方が細かい |
| タブの並べ替え・解除・複数操作 | ドラッグ並べ替え、アプリ名／ウィンドウ名での並べ替え、別ワークスペースへの移動、複数選択、左右や他のタブの一括解除 | 並べ替え、グループ間移動、複数タブの選択・移動・終了 | 基本操作は共通。WindowTabs はグループエディタも備える |
| タブ／ペイン固定 | タブを固定して先頭に保ち、ペイン固定でタブ切替時に維持 | タブをグループ内で固定 | 固定対象と切替時の意味が異なる |
| 音声表示 | タブに再生中アイコン。Chromium 系ブラウザはウィンドウ単位で判定 | README 上、同等の機能は確認できず | WindowDock の独自機能 |
| タブ位置・レイアウト | 上下左右、自動で隠す、混雑時に二段表示 | 水平・垂直、表示スタイルや自動非表示など | 見た目のカスタマイズは WindowTabs の選択肢が多い |

## WindowTabs にあり、WindowDock では確認できなかった機能

### 切り替え・検索

- タブ／ウィンドウを名前で検索し、該当ウィンドウへ直接切り替える。グループ自体の検索もある。
- Ctrl+1〜9 / Alt+1〜9 で番号による切替、任意のウィンドウやグループに割り当てるショートカット。WindowDock は **Control+Shift+1〜9** で現在のタブを除く先頭9タブへ切替可能。番号はタブの順番で決まり、個別には割り当てない。
- 直前に使ったタブへ戻る操作。WindowDock はタブメニューと **Control+Shift+0** に対応。
- マウスホイールでタブ切替や並べ替え。WindowDock は水平タブバーで全タブが見えている場合のホイール切替と、Shift+ホイールによる隣接タブの並べ替えに対応。タブにカーソルを置くとウィンドウの静止プレビューを表示する。設定で有効にすれば、ホバーによるタブ切替も可能。リーダーキーによる選択は未対応。
- 任意設定の Alt+Tab 置き換え。
- コマンドパレットから操作・設定を検索して実行し、コマンドラインからグループ化やワークスペース復元を行う。

WindowDock は **⌘F / Tab → Find Window** から、全ワークスペースのアプリ名・ウィンドウ名・まとめたタブ・ワークスペース名を検索して切り替えられる。コマンドパレットは未対応。

### グループ整理

- 複数グループとタブを一覧し、グループ間移動や分割を編集してから保存するグループエディタ。
- タイトル、ウィンドウクラス、コマンドラインなどを使ったアプリルールと、アプリをまたぐグループ。
- タブの色、グループごとの色、ピン留め、アプリ順・タイトル順の並べ替え。
- ファイルをタブにドラッグして対象ウィンドウを前面に出し、エクスプローラーではそのままファイルをドロップする操作。

### 復元・外観・補助機能

- 復元時に起動していないアプリを起動して、保存したワークスペースへ追加する。
- テーマ、タブ形状、色、不透明度、閉じるボタン表示などの細かな外観設定。
- 右ボタンを使うマウスジェスチャー、タスクバーのグループ化。
- 設定のエクスポート／インポート／初期化。

## WindowDock にある独自の強み

- 分割ペインを入れ子にし、縦横それぞれ最大 4 分割まで構成できる。
- 表示中の複数ペインをひとつのタブとしてまとめ、元のレイアウトを保って切り替えられる。
- ペインを固定して、Control+Tab の切替対象を制御できる。
- タブを固定して、並べ替え後もタブバーの先頭に保てる。固定状態は保存・復元される。
- 「+」からアプリを選んで新規ウィンドウを開き、そのままワークスペースに追加できる。
- 再生中のアプリをタブに表示し、Chromium 系ブラウザでは再生中の個別ウィンドウを識別できる。
- 起動時に複数の保存済みワークスペースから復元対象を選び、保存レイアウトや固定ペインとともに復元できる。

## 優先順位の提案

1. **完了: ウィンドウ検索**: アプリ名・ウィンドウタイトル・まとめたタブ・ワークスペース名で検索し、選択したタブやワークスペースへ移動する。
2. **完了: 番号によるタブ切替**: Control+Shift+1〜9 で、表示順に他のタブへ直接切り替える。
3. **完了: 直前に使ったタブへ戻る**: タブメニューと Control+Shift+0 から実行できる。
4. **対象外: タイトル条件による自動追加**: 新規ウィンドウの自動追加はアプリ単位に限定する。
5. **完了: ペインの均等化**: 表示中のタブの「ペイン → この分割を均等にする」で、通常グリッドは列幅と行高を揃える。入れ子の場合は対象ペインを含む最も近い分割だけを等分し、他の分割比率は維持する。
6. **次の候補**: グループ編集やファイルドロップなど。中心機能への効果と実装コストを見て、小さく追加する。

色・ジェスチャー・外観の細分化などは便利だが、WindowDock の中心目的に対する優先度は低め。

## macOS での適用上の注意

- WindowTabs のタスクバー統合や Windows の Alt+Tab 置き換えは、Dock・⌘Tab と役割が異なるため、そのまま移植する対象ではない。
- グローバルショートカットは macOS と各アプリの既存操作との競合を避ける必要がある。
- タブ検索や直接切替を実装する場合も、ウィンドウ一覧の取得・切替は WindowDock の Accessibility API とワークスペース状態に沿って行う。
- WindowTabs の機能数を揃えること自体を目的にせず、WindowDock の「複数ワークスペースでウィンドウ切替の負担を減らす」という価値に沿って優先する。
