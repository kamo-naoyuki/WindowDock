# 選択したアプリの自動グルーピング

## 目的

- WindowTabs のように、選択したアプリの新しいウィンドウを指定したワークスペースへ自動でタブ追加する。
- タブの右クリックと空白タブのどちらからでも設定できるようにする。
- 未登録のアプリ、手動での追加・解除、既存のランチャーの操作は変えない。

初版はワークスペース単位とし、ペイン固定やウィンドウタイトルによる振り分けは対象外とする。

## 実装状況

初版を実装済み。計画から次の点を変更・具体化した。

- **追加先の識別**: 永続 ID は導入せず、保存レコードの名前で対応付ける。名前変更は直後に保存し、ルールも新しい名前へ移す。
- **ウィンドウの識別**: ウィンドウ番号（AX と、他の Space・最小化中も含む CGWindowList）で判定し、取得できない場合は AX 要素で判定する。
  ウィンドウ番号はログイン中に再利用されない。基準一覧・新規検出・手動解除の除外は同じ台帳で管理し、アプリの終了またはルールの解除で破棄する。
- **追加時の表示**: 自動追加したタブは選択しない。空いているペインがあれば表示し、なければ現在のペインの背後で待機させる。
  前面アプリでそのウィンドウにフォーカスがある場合だけ、既存のフォーカス追従でタブが選ばれる。
- **復元**: ルールだけを持つワークスペースは復元確認を出さずに開く。復元確認中はルールの変更もできない。
- **確認画面**: アプリ選択と追加先変更の確認は、名前変更・削除と同じモーダルで表示する。
  アプリ選択はチェックボックスの一覧で、このワークスペースに登録済みのアプリ（チェック済み）、最近使ったアプリ最大12件、
  起動中のアプリの順に並べる。他のワークスペースに登録済みのアプリには登録先を併記し、
  一覧にないアプリは「その他のアプリを選ぶ…」のパネルから追加する。保存時に追加と解除をまとめて反映する。
  追加先変更の確認をキャンセルした場合は解除も行わない。
- **対象外のウィンドウ**: 検出時に最小化・フルスクリーンだった新規ウィンドウ、休止中に開かれたウィンドウは、後からも取り込まない。
- **通知の欠落**: AX の作成通知に加え、監視中のアプリだけを6秒ごとと、そのアプリがアクティブになったときに再確認する。
- **失敗の通知**: 自動追加の登録失敗は、監視中のアプリごとに1回だけ通知し、以降はログだけに残す。
- **閉じたワークスペース**: ルールは保存したまま監視しない。開き直すと既存ウィンドウを基準として取り直す。

テストは `Tests/WindowDockCoreTests/AutoGroupingTests.swift` と
`bash Tests/WindowDockUITests/run-smoke.sh --auto-group-only`。実機での各アプリ（Finder、Safari、Terminal、VS Code）の確認は未実施。

## UI

### タブの右クリック

実ウィンドウのタブに次の項目を追加する。

- **「Finder の新しいウィンドウを自動でこのワークスペースに追加」**: チェックで登録・解除する。アプリ名は対象タブから取得する。
- **「別のアプリを選ぶ…」**: 共通のアプリ選択画面を開く。

チェック解除は自動追加だけを止め、追加済みのタブは残す。
空白タブの右クリックにはアプリを推測した項目を出さず、アプリ選択の入口を表示する。

### メニュー

メニューバーの「ワークスペース」メニューとワークスペース名のメニューに
**「新しいウィンドウを自動で追加するアプリ…」** を置き、共通のアプリ選択画面で複数アプリを一括で登録・解除する。
復元確認中や終了処理中は無効にする。

### 空白タブ

既存の「開いているウィンドウ」と「インストール済みのアプリ」を維持する。
インストール済みのアプリは複数列のグリッドで縦にスクロールする。

- アプリをクリックすると、従来どおり新しいウィンドウを開いてそのタブに追加する。
- 「アプリを複数選択」で複数のアプリをチェックし、
  「%d個のアプリで新しいウィンドウを開く」か「%d個のアプリの新しいウィンドウを自動でこのワークスペースに追加」を選ぶ。
- 自動追加の登録ではアプリを起動せず、新規ウィンドウも要求しない。
- このワークスペースに登録したアプリを一覧表示し、ウィンドウが1枚もなくても登録解除できるようにする。
- 既存のランチャーをクリックしただけでは自動追加を有効にしない。

すべての入口で同じ登録・解除処理を使う。

## 動作ルール

### 登録と追加先

- 標準では登録後に開かれたウィンドウだけを対象にする。
- 登録時に「今開いている3件も追加」のように、追加可能な既存ウィンドウも取り込めるようにする。既定ではオフ。
- 1アプリの自動追加先は1ワークスペース。1ワークスペースには複数アプリを登録できる。
- 他のワークスペースに登録済みなら「追加先を『仕事』から『個人』に変更」と確認する。既存タブは移動しない。
- 手動で別のワークスペースへ追加する操作は許可し、自動ルールで取り戻さない。

### 自動追加

- 通常の管理可能なウィンドウだけを追加する。保存ダイアログ、シート、補助パネル、WindowDock 自身は対象外。
- どこかのワークスペースで管理中のウィンドウは追加しない。
- 自動追加だけでワークスペースを前面に出したり、フォーカスを奪ったり、現在の選択タブを切り替えたりしない。
- 分割時もルールの保存先はワークスペースまでとし、既存のペイン選択・固定の制約を守る。
- 最小化やフルスクリーンを自動で解除して取り込まない。

### 解除・休止

- 手動で解除したウィンドウは、開いている間は自動で取り込み直さない。閉じて新しく開いたウィンドウは対象に戻す。
- 自動化をオフにしても追加済みのタブは残す。
- 追加先が閉じている、最小化中、復元確認中の場合は休止し、勝手に開いたり復元確認を迂回したりしない。
- 再開時は既存ウィンドウを基準として取り直し、休止中に開かれたものを一括で取り込まない。
- アプリの再起動後もルールは有効。監視中にアプリが起動した場合、その起動で開かれるウィンドウも対象にする。
- WindowDock の再起動時はルールを復元するが、すでに開いているウィンドウを新規扱いしない。
- ルールのある空ワークスペースは自動削除しない。明示的に閉じる場合は休止、削除する場合は紐づくルールも削除する。

## 設計

### 既存コードの利用箇所

| 処理 | 場所と変更方針 |
|---|---|
| タブの右クリック | `Sources/WindowDock/WorkspaceChromeView.swift` の `tabContextMenu(for:)` に入口を追加 |
| 空白タブと最近使ったアプリ | `Sources/WindowDock/NewTabPage.swift` に登録済みアプリと選択の入口を追加 |
| アプリ選択パネル | `Sources/WindowDock/WorkspaceController.swift` の既存パネルを参考に、起動と登録の操作を区別 |
| 候補取得と AX 操作 | `Sources/WindowDock/Accessibility.swift` と `WindowAccessClient` に監視・アプリ別列挙を集約 |
| ウィンドウの登録・解除 | `Sources/WindowDock/WindowSession.swift` の既存の検証・登録・元フレーム保存を再利用 |
| 全ワークスペースの調整 | `Sources/WindowDock/App.swift` から自動グルーピング用コーディネータを接続 |
| 永続化 | `Sources/WindowDock/SavedLayout.swift` の保存・復元・名前変更・削除との整合を取る |

既存の `WindowSession.add` は追加後に最後のウィンドウを選択し、空ペインも埋めるため、
監視からそのまま呼ばない。共通の登録処理を使いつつ、自動追加では選択・表示状態を維持できる経路を用意する。

### ルールと識別

- アプリは表示名や PID ではなく bundle ID で保存する。bundle ID を取得できないアプリは理由を表示して登録不可にする。
- 追加先は名前変更で壊れないワークスペースの永続 ID を使う。既存の保存データには ID を補完し、旧形式との互換性を維持する。
- 空ワークスペースでもルールが保存されるように、現在の「ウィンドウがある場合だけ保存する」経路を見直す。
- ウィンドウの重複判定は既存の同一ウィンドウ判定を利用する。PID やウィンドウ番号の再利用で別ウィンドウを除外しない。
- 手動解除による除外はウィンドウの生存期間だけ保持し、対象アプリの終了時に破棄する。

### 検出と競合防止

1. 登録済みアプリの実行中インスタンスを把握し、起動・終了通知で監視を付け外しする。
2. 登録・監視再開時に既存ウィンドウの基準一覧を取得する。基準取得の失敗を空一覧扱いしない。
3. AX のウィンドウ作成通知を契機に、そのアプリだけを再列挙する。
4. 作成直後に属性が揃っていない場合は上限付きで再試行する。通知の欠落には対象アプリだけの低頻度再確認を使う。
5. MainActor 上でルールの有効性、追加先の状態、全ワークスペースの登録状態、手動解除の除外を再確認して追加する。

- 全アプリを高頻度でスキャンしない。AX 呼び出しのタイムアウトと通知の集約を入れ、UI を止めない。
- ランチャー、復元、手動追加、ドラッグと競合した場合は明示的な操作を優先する。
  特に空白タブの起動処理が待っているウィンドウを、自動追加が先に取得しないよう連携する。
- 処理中にルールを変更・解除した場合は、古い検出結果を適用しない。
- 権限不足・監視不可・登録失敗は既存の通知とログで明示し、同じ失敗を連続して通知しない。

自動グルーピングの調整処理は `App.swift` に直接増やさず、独立したコーディネータに置く。
純粋なルール判定は `WindowDockCore`、AX・UI・セッションの調整は `WindowDock` に分けてテストできるようにする。

## 実装フェーズ

1. **ルールと永続化**
   - ワークスペースの永続 ID、アプリとの対応、旧データの移行、空ワークスペースの保存を実装する。
   - 名前変更・閉じる・再開・削除でのライフサイクルを揃える。
2. **登録 UI**
   - 右クリックと空白タブに共通の登録・解除・追加先変更を接続する。
   - 既存ウィンドウの取り込み確認と登録済みアプリ一覧を実装する。
3. **新規ウィンドウの自動追加**
   - 対象アプリの監視、選択を変えない追加、手動解除の除外、明示操作との競合防止を実装する。
   - Phase 3 までは未完成の登録 UI を利用者向けに公開しない。
4. **実機確認と案内**
   - 新しい表示文字列を `L()` 経由にし、en/zh/ko/es を追加する。
   - README には利用者向けの登録・解除方法と休止条件だけを追記する。

## テスト計画

- **ユニットテスト**（`swift test`）
  - 登録・解除、1アプリ1追加先、追加先の変更、旧データの移行と保存・復元。
  - 基準一覧と新規検出、手動解除の除外、アプリ再起動、古い非同期結果の破棄。
- **スモークテスト**（`bash Tests/WindowDockUITests/run-smoke.sh`）
  - 右クリックと空白タブで同じルールになり、登録だけではアプリを起動しない。
  - 既存分の取り込みは明示的に選んだ場合だけ行われる。
  - 自動追加で選択タブ、前面アプリ、固定ペインを変えない。
  - ランチャーや手動追加との競合でも二重登録や追加先の横取りが起きない。
  - 手動解除後の再取り込み、閉じた追加先の再表示、復元確認の迂回が起きない。
  - 権限不足、属性取得失敗、監視途中のアプリ終了でも既存ウィンドウを新規扱いしない。
- **実機確認**
  - Finder、Safari、Terminal、VS Code で、起動中の新規作成とアプリ起動時のウィンドウを確認する。
  - 保存ダイアログ、最小化、フルスクリーン、複数ワークスペース、WindowDock 再起動を確認する。

## 初版の完了条件

「仕事」ワークスペースで Finder を登録すると、その後に Finder で開いた通常ウィンドウが
「仕事」に1回だけタブ追加される。右クリックと空白タブのどちらからも登録・解除でき、
未登録アプリ、手動解除したウィンドウ、他のワークスペースのタブには干渉しない。
